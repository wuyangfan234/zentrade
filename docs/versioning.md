# 版本与构建标识

产品版本固定为 **0.55.0**。修复、功能开发和常规发布不再人工升号。

- 应用、Python 元数据、前端包、根 `VERSION` 使用相同固定值；一致性测试防止意外漂移。
- `/health` 的 `version` 与 `/api/data/version` 的 `version` 同源（后者保留显示用 `v` 前缀）。两者同时返回 `revision`。
- Docker 构建时传 `--build-arg ZENTRADE_COMMIT=<Git SHA>`；镜像 OCI revision 与运行环境使用同一参数。GitHub 镜像工作流已经自动传入 SHA。
- 本地源码启动自动读取所在 Git 工作树 HEAD。没有 Git 元数据且未传构建标识时显示 `unknown`，不能作为部署验收证据。
- 设置页显示短提交号，版本徽标悬停可查看完整提交号。核对部署必须同时比对提交标识，不能只看固定版本。
- 更新检查按 GitHub 默认分支提交祖先关系比较：远端领先才提示更新，本地领先不提示；历史无关或无法比较时显示检查失败，不误报最新。缓存按版本和构建提交隔离。
- 变更写入 `CHANGELOG.md` 的 `[未发布]`，历史语义版本保留，不逐次创建新版本号。
- 依赖版本、API/存储契约版本以及独立移动端外壳的版本规则不在本次固定范围。

固定版本不代表各部署已同步；部署授权、测试、备份、回滚和运行版本回读要求不变。
